## 크로미움 기반 새로운 Edge, 왜 주목할까

![microsoft-edge-chromium 이미지](/images/posts/microsoft-edge-chromium/img-01.png)

Microsoft는 오래된 Trident 엔진을 내려놓고, 크로미움 기반으로 Edge를 완전히 새로 만들었습니다. 같은 크로미움이라면 Chrome과 뭐가 다를까요? 실제 사용으로 확인해보았습니다.

## 메모리: Chrome의 고질병을 해결하다

**Chrome의 문제**: 탭과 확장 프로그램이 많아질수록 메모리를 가파르게 먹습니다. 같은 크로미움 기반이라면 비슷할 것으로 예상했지만, 결과는 달랐습니다.

### 초기 상태 (새로 실행)
- Edge와 Chrome 모두 비슷한 수준의 메모리 사용

### 실전 사용 (탭 20개, 확장 10개)
| 항목 | Chrome | Edge | 개선도 |
|------|--------|------|--------|
| 메모리 | 1.2GB | 850MB | **30% 감소** |
| 반응속도 | 지연 감지 | 부드러움 | 명백 |

**이유**: Microsoft가 메모리 최적화에 특별히 신경 썼습니다. 같은 엔진이라도 환경 설정의 차이가 큽니다.

## 확장 프로그램: 호환성 걱정 없음

Edge의 자체 마켓플레이스는 크롬 스토어에 비해 작습니다. 하지만 여기가 중요합니다:

**Chrome 확장 프로그램은 그대로 설치 가능합니다.**

- uBlock Origin, LastPass, React DevTools, Redux DevTools 등 주요 확장 모두 설치 완료
- 호환성 문제 없음
- 실제로 Chrome 스토어의 링크를 열면 Edge에서 설치를 제안합니다

## Mac 터치바: Safari 수준의 지원

Mac 사용자가 Chrome을 쓸 때의 가장 큰 불편은 **터치바의 부족한 지원**입니다. Safari는 터치바를 우아하게 다루지만, Chrome은 거의 무시합니다.

### Edge의 터치바 지원

| 기능 | Chrome | Edge | Safari |
|------|--------|------|--------|
| 탭 전환 | ✗ | ○ | ○ |
| 뒤로/앞으로 | ✗ | ○ | ○ |
| 새 탭 | ✗ | ○ | ○ |
| YouTube 재생바 | ✗ | ✓ | ✓ |

**YouTube 재생바 컨트롤**이 정말 감동적입니다. Mac에서 터치바를 쓰고 있다면, 이것만으로도 전환할 이유가 충분합니다.

## 개발자 경험: 완전히 같습니다

DevTools는 Chrome과 99% 동일합니다. F12를 누르면:
- 같은 인터페이스
- 같은 기능
- 같은 단축키

전환하면서 개발 효율성이 떨어질 일은 없습니다.

## 마이그레이션 팁

### 데이터 자동 이관
설치 시 Chrome에서 자동으로:
- 북마크
- 비밀번호
- 자동완성 데이터
- 결재 정보

모두 옮겨집니다.

### 추천 설정
1. 확장 프로그램은 처음에 필요한 것만 설치
2. 동기화 설정 확인 (Microsoft 계정)
3. 홈 버튼 켜기 (옵션)

## 이렇게 평가합니다

**메모리 효율**: ★★★★★  
**호환성**: ★★★★★  
**Mac 경험**: ★★★★★  
**개발자 친화성**: ★★★★★  

같은 크로미움이라도 어떻게 조율하느냐에 따라 완전히 다른 경험이 됩니다. Chrome에서 옮길 이유가 명확합니다.

## 마치며

"탈 크롬"은 거창한 표현이지만, 현실적으로는 합리적인 선택입니다:

- **메모리 부담이 줄어든다**: 같은 작업을 더 효율적으로
- **터치바가 살아난다** (Mac): Mac의 장점을 다시 느낀다
- **설정에 손쓸 일이 없다**: 그냥 Chrome과 같이 쓴다

이미 사용 중인 Chrome 북마크, 확장, 설정을 그대로 옮기고, 메모리 여유를 얻으세요. 한 번 시도해볼 가치가 있습니다.
